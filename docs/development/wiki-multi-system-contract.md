## Identity, authority and navigation

The existing Site → Wiki → private Rules Core tunnel and named operation allowlist remain the only runtime reference transport. Core lists permitted descriptors and returns ruleset ID, fingerprint and native rule envelope. Use `api.openRulesetReader(rulesetId)` from app bootstrap: it discovers the exact authorized descriptor and returns a snapshot-pinned reader. No fallback to first-party for missing, denied, malformed or stale contexts. Core's private reference endpoints currently use the same foreign-catalog distribution policy as public reads (first-party authenticated exception only). F leaves that policy unchanged; no additional preview entitlement or authorization layer is approved. Use isolated test-only existing distribution approval for runtime acceptance. Fixture-driven renderer development needs no policy change. Do not modify policy or use public endpoints. The catalog navigation workstream must replace the temporary unavailable-route guard only when it can bind an authorized context and isolate all index, detail and history state.

`rules-context.js` is authoritative: context = { rulesetId, fingerprint, campaignId, campaignRevisionId }. Base ruleset identity is never campaign identity. Current readers reject any campaign; future authoritative campaign revision must come from Core, not Site roles, browser state or fabricated IDs. The descriptor and every read must match the exact ruleset and fingerprint. Fingerprint change requires re-discovery and a new context, not mixed pages.

Canonical paths (relative to hosted tool base): /rulesets/{rulesetId}, /rulesets/{rulesetId}/types/{kind}, /rulesets/{rulesetId}/rules/{ruleId}. Legacy first-party /rules/{id}, /references/{id}, category-family routes, /types/{kind}, /all and / remain supported. Explicit malformed/foreign qualified paths must not silently become first-party. Use ruleRoute/categoryRoute/catalogRoute for new links. Do not use a foreign entity ID in a legacy unqualified path. Preserve existing first-party links until navigation integration.

## Presentation interfaces

`native-presentation.js`: createRulesetReader(api, context) provides context, search(filters), resolve(ruleId), hrefForRule(ruleId). Resolve returns the exact Core envelope {rulesetId,fingerprint,rule:{id,name,kind,definition}}. Core definition is the full native record, including wrappers, not necessarily a uniform gameplay payload. Never mutate or flatten it in the common adapter. createPresentationInput(context,envelope,reader,{toolBasePath,renderSource,lifecycle}) supplies context, rule, record, source, sourcePackage, references, hrefForRule, renderSource and lifecycle. Source can be absent; do not invent attribution. The active dispatcher passes the optional app.renderNativeSource(input) hook through to the common presentation input. The hook returns a safe DOM node and may be supplied by the attribution workstream. A source hook supplies a safe DOM node; retain authored provenance and display catalog license when an authoritative source is available. F adds optional manifest-derived metadata to the exact authorized descriptor (Core PR #212). `reader.packageDescriptor` and `input.packageDescriptor` preserve that metadata independently of entity provenance; absent metadata remains visibly unavailable. `discoverAuthorizedRuleset` is the shared discovery boundary used by both context and package discovery. Manifest-only changes need not change the entity fingerprint; rediscover metadata when opening a reader.

createNativeRendererRegistry(fallback) registers {id,supports(input),render(input),priority}. supports is a pure structural/capability predicate (kind alone is insufficient for incompatible schemas); equal-priority ambiguity is an error. render returns a detached DOM node or Promise of one. The shared generic fallback displays the complete record as inert text/DOM, including tables and nested values. It never executes inline tags, Markdown, HTML, or mechanics. Build richer structured-entry/tag rendering on renderStructuredContent; unknown shapes remain readable, not discarded. Explicit native ID references may be resolved via the context-bound reader; do not infer cross-catalog links from display names or 5etools tags. Existing native-rule-detail.js and resolved rule-renderers.js stay available; do not route foreign records through first-party specialized dispatch. Reconcile existing renderers by adapting input contracts, not duplicating layouts. The active native dispatcher uses the same registry for every native envelope. The first-party compatibility adapter has priority -1000 and preserves the current layout; structural adapters with ordinary priority supersede it. Unmatched foreign records use the shared generic fallback. New renderers return a detached node or array of nodes (or a Promise of either); the dispatcher supplies shared navigation chrome and mounts only current results. New renderers use renderNativeAttribution(input) or the same source hook for entity provenance only. The active dispatcher adds the package notice once for specialized and compatibility views; generic fallback owns its notice. Do not append package notices within specialized renderers. The legacy resolved-rule variation dispatcher remains intact; no unsupported campaign authoring is activated.

Registration ownership: native-renderer-registration.js is the composition root. Each independent workstream exports registerNativeRenderers(registry) in its preinstalled native-renderers-class.js, native-renderers-creature.js or native-renderers-reference.js slot. Register new modules there; do not edit native-rule-detail.js or app.js to add a renderer. Use unique namespaced IDs and structural predicates; coordinate overlapping predicates/priority. The active registry is app.nativeRendererRegistry. Direct fixture callers may instantiate createWikiNativeRendererRegistry().

The detail pane reads app.rulesContext when bound by catalog navigation, otherwise the first-party wikiIndex snapshot. Catalog navigation owns setting/replacing app.rulesContext and app.rulesetReader together from an authorized discovery result, supplying the unqualified native rule ID to renderRuleDetailPane, and canceling old detail reads before switching contexts. The pane validates and reuses app.rulesetReader when present, preserving its exact identity and any additional authorized package descriptor. A stale or mismatched bound reader fails closed. The context and reader must be replaced together, never mutated in place. The pane resolves the requested record through the pinned reader when rulesContext is present; legacy first-party reads are also verified against the index fingerprint and requested ID. app.rulesContext must not be set to an unauthorized or guessed catalog. Existing foreign-route guard remains until navigation integration.

createRenderLifecycle() belongs to the owning surface; begin(context,ruleId) invalidates the previous lease and returns {key,signal,isCurrent}. Cancel on teardown, selection changes, catalog changes or navigation away. The live pane now cancels the preceding lease on selection and full app render; scope and empty-index transitions cancel it as well. The lease also checks the selection serial, bound context, index snapshot and mounted surface. Check isCurrent before every async success/error DOM commit; mountNativePresentation handles the top-level detached result. Nested async sections must also use the lease and check their own current mount; AbortSignal is advisory (existing private transport has no signal parameter). Retain existing render serial checks and explicit presentation hooks. No mutation observers.

## State

referenceKey(rulesetId,ruleId) is stable across revisions and suitable for identity/bookmarks/recent history. Any content cache, search cache, resolved reference cache or revision-sensitive reading position uses snapshotKey(context,...parts); readingKey(context,ruleId,view) includes the rule and view. Tuple serialization avoids delimiter collisions. Catalog fingerprint participates in cache and expansion state, not stable identity. Campaign identity and authoritative revision participate in snapshot keys; unrevisioned campaign state cannot enter reusable snapshot caches. Never reuse per-user access decisions or private record contents across sessions. First-party legacy storage remains unchanged while guarded; migrate legacy unqualified values only as first-party when explicitly reconciling state. Do not write foreign history into legacy unqualified stores. Do not persist campaign data or authoritative gameplay resolution.

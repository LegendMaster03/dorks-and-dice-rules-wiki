## Transport and capability

The first-party descriptor advertises `capabilities.originReferenceContractVersion: 1`. The exact snapshot-pinned reader preserves this capability. Older Core and foreign readers expose null and reject Origin-specific calls without a network request. A browser sends only named operations; the Wiki dispatcher accepts [rulesetId, fingerprint, familyOrExactId] and maps one operation to one private GET. The Core ticket and exact fingerprint are checked before projection. Stale 409, invalid 400, missing/unsupported 404, denied 401/403 and unavailable 503 propagate without fallback. All successful envelopes carry contractVersion, rulesetId and fingerprint; readers additionally check target identity. Do not combine results across readers or snapshot revisions. Existing native search/detail operations are unchanged.

Hierarchies (biological, upbringing, construct-components, characteristics, backgrounds, construct-options) and reverse relationships are complete bounded families, not paginated streams; Core fails rather than silently truncating when the scanned family exceeds 256 records. Use native search for ordinary paginated categories. No client-side global filtering of partial pages.

### Schema details and reference examples

- Hierarchy row: id, name, kind, parentId, selectable, defaultUpbringingId, acquisitionMethodIds, status, rulesStatus, componentCategory, ancestrySelectionRequired, capabilities, compatibleComponentCapabilities, producesDefinitionId, characteristicFamily. A null field is unavailable/not applicable, not a synthesized value. Selectability applies only to biological and life-experience source records; characteristic/component/option rows have null selectable in the updated Core candidate. Build parent-child edges using parentId within the complete biological or upbringing family; children are the exact matching IDs. Use ordinary detail for the selected entity.
- Source lineage: root-to-selected rows, id/name/kind/sourcePath/inheritedSource/definition/traitOccurrences. Occurrences contain sourceId, path, index, canonicalTraitId, localId and the complete expanded trait. Canonical identity can be null for inline traits. The source-qualified path is not the canonical ID.
- Direct reference: methodId, referenceOnly, candidates (sourceId/path/slot/offeredValue/authoredParameters/requiredChoices/unresolvedEvidence/sourceRestriction), fixedValues (slot/value/sourceId/path), issues. Null for nonselectable/incomplete or non-biological source. FixedValues are limited to unambiguous native source offers, not earned values or a complete character. Example: Wood Elf fixed walkingSpeedFeet 35 from ancestry.elf.wood; species.elf's 30 offer is explicitly superseded. Red Dragonborn root Breath Weapon occurrence trait.breath-weapon at /traits/2 binds authoredParameters.damageType fire and a 30-by-5-foot line. No grant or selection eligibility is implied.
- Method envelope: previewOnly, scope, methods. Each method preserves reference.ruleId/methodId, name, specializes, stage, createsNewIndividual, operation, support, defaultAvailability and definingCreatureTypeId. Null authored stage/creation markers stay null. For Dragon, biological defaultAvailability is available; Rite of Rebirth explicitly changes an existing individual and is a verified-reconstruction-plan transport. Use existing rule detail for full authored descriptions.
- Trait reverse: complete, traitId, sources (sourceId/name/kind/path/relation). Biological-occurrence points to /traits/index; construct-operational-reference points to /operationalOriginTraitIds/index. Do not treat operational links as biological inheritance.
- Component envelope: componentId/category (componentCategory), sourcePath, original definition, configuration (definitionId/name/materialSlots/defaultRecipeId/constructionVariants/modeIds/baseCapabilities/requiresAnyOf/mountInterfaces/acceptsMountInterfaces/powerSourceRequired/requiresContinuousPower/designs/enhancements/powerSources/issues), recipes, materialCompatibilityAvailable, materialAssignmentOptions. Example locomotion unit offers wheeled-drive as a compatible design and steel as an assignment candidate; physical suitability is not available.
- Component reverse: targetId, complete, sources with exact source-qualified path and relationship label (compatible-design, compatible-enhancement, compatible-power-source, material-assignment-candidate, default-recipe, variant-recipe), output (id/name/kind/path, or null), recipes (id/name). Recipe output is a forward pointer from the requested recipe, not an invented source property.
